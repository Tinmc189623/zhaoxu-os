1.3 结构约束

  • 内核不含驱动、不含桌面、不含应用。AHCI、PS/2、鼠标、RTC、串口由 Ring3 /bin/drivers 独占；内核只保留 CPU、内存、调度、IPC 与 VFS 核心。构建后 nm out/kernel.elf 不应出现 ahci_*、acpi_init、serial_init、keyboard_*、mouse_*、pit_init、pci_* 等符号。
  • 内核 freestanding。无 libc、无 STL、无异常与 RTTI、默认禁用浮点与 SSE（-mgeneral-regs-only）。Ring3 字体源码是唯一例外。
  • 版本单一来源。version.cfg 是唯一版本源，make version 同步 version.h、motd、/etc/version 与 README。
  • 名称契约。Yuanshuo、OS_5P、IO/287、Limine、Aqua Desktop Environment、Desktop Window Compositor、Desktop Window Manager、ZAF、Z64 不得改名或缩写。

2启动链

2.1 两条固件路径

UEFI 下固件直接加载 Limine 的 EFI/BOOT/BOOTX64.EFI。Legacy BIOS 下 SeaBIOS 读取 Limine 的引导扇区（ISO 上是 limine-bios-cd.bin，已安装盘上是安装器写入的 MBR 扇区），stage 1 从 LBA 8（MBR）或 LBA 34（GPT 的 BIOS boot 分区）加载 stage 2，stage 2 用自带的 FAT / ISO9660 驱动读取 limine.conf 与 limine-bios.sys。两条路径此后都进入 Limine 协议。

UEFI    : 固件 → BOOTX64.EFI → limine.conf → kernel.elf
Legacy  : SeaBIOS → limine-bios-cd.bin / MBR stage1 → stage2 → limine.conf → kernel.elf

2.2 Limine 协议与 boot_info

kernel/boot/limine_boot.c 实现 Limine 协议：在 Limine 提供的 HHDM 页表上安装 64 GiB 恒等映射，映射 BSS 引导栈窗口，然后把内存映射、帧缓冲、RSDP、可执行地址与模块整理成 struct boot_info（magic 0x5A4F5331）。boot_info 的字段顺序必须与 kernel/include/boot.h 同步；模块与帧缓冲地址经 HHDM 换算成物理地址。

模块用途
kernel.bin安装器与 legacy BIOS 使用的扁平镜像
MiSans.ttf启动字体，交给 Aqua Desktop Environment
WALL.RGB预转换壁纸原始像素，省去启动时解码

内嵌 initramfs 由 tools/initramfs-compress.rb 压成 ZIR1 包装的 zlib 流，内核在挂载 rootfs 之前解压，这保证 legacy BIOS 的 install/KERNEL.BIN 控制在 stage 2 的 448 KiB 缓冲之内。

Limine 12 没有 ext4 驱动。已安装系统的 KERNEL.ELF、MiSans.ttf、WALL.RGB 全部放在 ESP 的 /boot/limine 目录，ext4 的 ZHAOXUROOT 不承载任何引导文件。

3内核 Yuanshuo

3.1 物理内存

kernel/mem/pmm.c 是位图页分配器：pmm_alloc_page、pmm_free_page、pmm_reserve_range，上限 PMM_MAX_PHYS 为 64 GiB，内部用 irqsave 自旋锁保护。PMM 在 vmm_init 之前就要能管理完整内存映射，已在 8 GiB 配置下验证。

3.2 虚拟内存

kernel/mem/vmm.c 提供 vmm_map_page、vmm_unmap_page、vmm_space_map_page。低端 64 GiB 用 2 MiB 页恒等映射（identity_map_high），NX 强制开启（enable_nx）；每个进程有独立 CR3，内核高半区共享，用户窗口在 PML4 slot 2 私有。

用户映像的段权限强制 W^X：CODE 为 RX，RODATA 为 R，DATA/ZERO 为 RW，数据段页带 NX。

3.3 进程、线程与调度

kernel/proc/thread.c 维护 32 槽的共享线程表。BSP 与 AP 都用 LAPIC timer 以 1 kHz 触发 sched_tick（PIT 只在启动时做一次 LAPIC 校准），量子 SCHED_QUANTUM_TICKS=10。上下文切换在 arch/x86_64/switch.S，保存/恢复 callee-saved 寄存器与 RFLAGS；线程栈 16 KiB，退出线程由下一次上下文切换在 sched_reap_local 中释放。

SMP 由 arch/x86_64/apic.c 解析 RSDP/XSDT/MADT，arch/x86_64/smp.c 把 ap_trampoline.S 复制到物理 0x7000，以 INIT-SIPI-SIPI 启动 AP。AP 必须在 ap_entry 里重新加载 GDT 与 IDT 并切换自己的 TSS，否则第一个中断就是三重故障。调度交接用 on_cpu 标记：旧线程完全切走之后，其他 CPU 才允许重新选中该槽位。

进程侧：fork 逐页复制用户映射（连同页权限）和 zfd 描述符，子线程在父进程 int 0x80 之后以 rax=0 返回；exec 先在全新地址空间装载镜像，成功后切 CR3、释放旧页并改写中断帧的 rip/rsp，失败则保留原程序。

描述符空间分两套：VFS 保留 3–18，新的 zfd 表从 64（ZFD_BASE）起，dup2 可以把 zfd 装到 0/1/2 并改写进程的 stdio 重定向表。kernel/proc/tty.c 为 0/1/2 提供终端语义：规范模式按行缓冲并回显，原模式逐字节返回，ioctl 支持 TCGETS/TCSETS/TIOCGWINSZ（80×25）/FIONREAD。

命名的端口消息上限 IPC_MSG_MAX 为 256 字节；ADE 桌面协议每条文本命令上限 ADE_TEXT_MAX 为 160 字节（含终止符），ade_text 在 UTF-8 边界截断。

3.5 VFS 与存储

/ 是 initramfs 支撑的 rootfs（initramfs 下层 + ramfs 写时复制）；/mnt 是按卷标 ZHAOXUDATA 选中的 FAT32 数据盘；没有数据盘时 /mnt/... 自动回退到 initramfs 内嵌的 /data/... 镜像。FAT32 支持文件级创建、覆盖与删除（kernel/fs/fat32_write.c，VFAT 长名、写侧 FAT 缓存、空闲槽复用）。ext4 ZHAOXUROOT 由 Ring3 /bin/ext4fs 经共享页 RPC 提供，内核不直接解析 ext4。

VFS 读描述符是只读的；写入走 write_file / unlink 系统调用路径，而不是 write。

3.6 系统调用 ABI

kernel/gfx/render.c 实现 Z64 1.0 光栅接口（kernel/include/zos_api.h，banner Z64 1.0）：矩形、线、圆角、裁剪、混合、纹理与字形绘制、SVG 光栅化。Ring3 复用同一份实现，Desktop Window Manager 与 Aqua Desktop Environment 都不直接访问帧缓冲像素。

4用户态与工具链

4.1 ZXE v1

用户 ELF 是链接到 RVA 0 的 PIE（-fpie/-fPIC，user/user.ld，不使用 -mcmodel=large），由 tools/zxe-pack.rb 转成 ZXE v1。加载器 proc/zxe_loader.c 在 [1 TiB, 1 TiB + 1 GiB) 内按 64 KiB 对齐随机选择基址（最多重试 64 次，失败即拒绝启动）。依赖按简单文件名从 /lib 加载。tools/zxe-check.rb 校验结构，tools/zxe-fixture-lib.rb 生成动态链接测试库。

4.2 C 库与 POSIX 层

newlib 4.6 是 C 库，由 tools/newlib.rb 用 clang 构建成 x86_64-elf 的 PIC 版本（必须 -fPIC，否则 PIE 重定位装不进随机基址）。user/lib/posix/libgloss.c 与 crt0.S 实现系统调用桩和 main(argc, argv, envp) 启动。ncurses 6.5 在树外构建，terminfo 条目为 initramfs/usr/share/terminfo/z/zhaoxu。nano 8.4 尚未完成 ZXE PIE 重链接。

4.3 Shell

GNU bash 5.3 由 tools/bash.rb 交叉构建并打包为 ZXE，运行在 /bin/bash。无帧缓冲启动时内核直接拉起 bash，可在串口操作。作业控制、信号与 toybox 尚未完成。

4.4 构建

cd src

6图形 API

6.1 OpenGL 1.1 软件实现

src/user/lib/opengl 是立即模式软件实现：矩阵栈、正交与透视投影、图元、深度测试、背面剔除、RGBA 纹理、GL_LIGHT0..7 光照与材质、混合、Alpha 测试、裁剪与 glReadPixels。构建时从 USER_CFLAGS 过滤 -mno-sse 并加 -msse2。缺显示列表、求值器、雾、选择/反馈、扩展与着色器。

6.2 Vulkan 1.0 软件 ICD

src/user/lib/vulkan 提供单 ICD 实现：实例、物理/逻辑设备、队列、内存、缓冲区、图像、渲染通道、帧缓冲、图形管线、命令缓冲、栅栏，以及 SPIR-V 1.0 解释器和 CPU 三角光栅化。没有 WSI/交换链、描述符集与 UBO、计算、深度/模板、多重采样与信号量。

规则 37/38 尚未满足。桌面仍走 Z64 软件光栅路径，OpenGL 与 Vulkan 是 Ring3 兼容层。发布说明必须如实描述上述限制，不得写成“默认 Vulkan、兼容 OpenGL”已达成。

7驱动模型

7.1 Ring3 驱动进程

Ada 驱动在 src/drivers/*.ads 用 pragma Export, Convention => C 导出符号，与 apps/drivers/ 的 C 胶水一起编译成 /bin/drivers（-mcmodel=large）。驱动进程拥有 0–4 GiB 恒等用户映射和 IOPL=3，DMA 与 MMIO 指针就是物理地址；pmm_alloc_page 通过 dev_alloc_page 系统调用实现。

7.2 共享页协议

页内容
头页请求状态机：块 I/O、RTC、信息查询
数据页块读写缓冲区
输入页键盘字符与鼠标状态的原子输入环
日志页内核日志环，由驱动输出到 COM1

四页定义在 kernel/include/dev.h。DEBUG_SERIAL=1 只用于开发，默认构建不含内核串口代码。AHCI 的 DMA 使用物理地址，依赖内核的恒等映射；命令头 prdtl 在偏移 2，FLUSH 这类无数据命令必须保持 prdtl = 0。

7.3 受信任能力

/bin/ext4fs 持有块设备能力并独占 ext4 解析。/bin/display 额外持有 display_cap，可用 memfd_phys 与 map_phys 取得扫描缓冲和 PCI MMIO BAR。casper/vga.ko 目前只是 Ring3 通用驱动镜像的副本，内核模块加载器尚未实现。

8安装器与磁盘布局

8.1 流程

/bin/apps/install.zxe 扫描 sys_disks，列出空白盘与既有 Zhaoxu 盘，自动选中一个目标，确认一次后按 GPT（默认）或 MBR（高级选项）安装。UI 另起一个 worker 副本执行写入，父进程通过共享页读取 SYS_INSTALL_PROGRESS（70）的 done/total 重绘进度条。完成后可点“立即重启”，走 SYS_REBOOT（69）。

内核侧 kernel/fs/install.c 自包含，不读取额外介质：写 MBR/GPT、写 Limine 的 BIOS 引导扇区与 stage 2、复制 UEFI 加载器、合成单段 ELF 内核、格式化 FAT32 ESP 与 ext4 根。

8.2 布局

安装目标识别按首扇区判断：空白盘、带 Limine 签名（EB 3C 90 + LIMINE）的盘、首分区类型为 0xEF/0x0C/0x0E 且从 LBA 2048 开始的盘。带 ZHAOXUDATA 的数据盘永不作为安装目标。

9Wayland 方向

目标架构写在 docs/superpowers/specs/2026-11-14-wayland-gbm-kms-design.md：Wayland 1.x 核心加 xdg-shell、wl_shm/dmabuf，缓冲经 GBM 分配，先 GPU 渲染/合成，再走 KMS 原子提交与页翻转。

阶段内容状态
M0传输层：socket、memfd、SCM_RIGHTS、eventfd/timerfd/epoll已实现并验证

10.1 三根支柱

OS_5P 是 XNU 式单镜像混合内核：Yuanshuo 当 Mach 角色，FreeBSD 15.1-RELEASE 当 BSD 角色，IO/287 当 IOKit 角色。三者编译进同一个 KERNEL.ELF，不是虚拟机、不是 bhyve 客户机、不是用户态 FreeBSD 进程。完整设计在 docs/superpowers/specs/2026-11-20-xnu-freebsd-design.md。

10.3 IO/287

IO/287 是内核内 freestanding C++ 的设备框架：匹配（总线探测或 vendor/device/class）、注册表（root → bus → device → function，属性可枚举）、引用计数对象模型（不开 RTTI 的类注册表）、驱动族（block / network / input / display / bus）。

  • 约束：无异常、无 RTTI、无 STL、无 C++ 运行时；静态构造不自动执行，由初始化钩子显式调用；对象从 personality VM API 预留区分配；注册表锁内不睡眠，探测在 kthread 上下文。
  • 边界：newbus 只保留给 personality 内部伪设备；现有 Ring3 /bin/drivers 继续运行，按设备迁移。
  • 许可：FreeBSD 为 BSD-2-Clause，与 GPL-2.0 兼容；sys/contrib/openzfs 与 sys/cddl（CDDL）不参与链接。
两条规则需要项目所有者修改 RULES.md（规则 41，AI 不得代改）。
r9：驱动只在 Ring3 —— 与内核内 IO/287 直接冲突。
r5：C 写内核、SPARK 写驱动 —— 与内核内 C++ 驱动族冲突。

11.3 桌面与安装

make run-iso 应直接进入 Aqua Desktop Environment，日志出现 limine: Loading executable、[ade ] font boot volume、[dwc] Desktop Window Compositor back buffer，并显示 Welcome 与 Calculator 两个窗口。ISO 改动要分别用 make run-iso（UEFI）与 make run-bios（SeaBIOS）验证。安装回归用 make run-install（GPT）与 make run-install-bios（MBR），随后只用目标盘启动。
